# Raw Block Export & Seam Analyzer Integration

## Overview

The raw block export adapter for `BatchParityGate` captures post-pass chunk snapshots across all target chunks, outputting dense paletted JSON representations for:
- **Order 1 (Shuffled A)** (`order1.json`): Kestrel, post-`FEATURES`
- **Order 2 (Shuffled B)** (`order2.json`): Kestrel, post-`FEATURES`
- **Vanilla / Oracle** (`vanilla.json`): decoded straight from the vanilla-written oracle region files, stage `FULL` (never regenerated by Kestrel)

This data enables full block-level cross-order and Kestrel-vs-Vanilla border seam inspection via `harness/tools/seam_analyzer.py` rather than relying only on aggregated cell counts or 64-bit hash digests.

## JSON Format Specification (`kestrel-raw-block-export-v1`)

```json
{
  "format": "kestrel-raw-block-export-v1",
  "seed": "3527749958874813416",
  "stage": "FEATURES",
  "order": "order1",
  "order_seed": 424242,
  "min_y": -64,
  "height": 384,
  "coverage": {
    "min_x": -8,
    "max_x": 8,
    "min_z": -8,
    "max_z": 8,
    "chunk_count": 289
  },
  "margin": {
    "min_x": -9,
    "max_x": 9,
    "min_z": -9,
    "max_z": 9,
    "stage": "CARVERS",
    "exported": false
  },
  "chunks": [
    {
      "x": -8,
      "z": -8,
      "xPos": -8,
      "zPos": -8,
      "default_block": "minecraft:air",
      "sections": [
        {
          "Y": -4,
          "palette": ["minecraft:bedrock", "minecraft:deepslate[axis=y]"],
          "data": [0, 0, 1, ...]
        },
        {
          "Y": 10,
          "palette": ["minecraft:air"]
        }
      ]
    }
  ]
}
```

### Key Format Guarantees
1. **Seed as Decimal String**: `"seed": "3527749958874813416"` prevents 64-bit long precision loss in JSON parsers.
2. **Explicit Signed Chunk Coordinates**: Both `x`/`z` and `xPos`/`zPos` store signed chunk coordinates and must agree; the strict loader (`validate_raw_export_v1`) rejects a payload where they don't.
3. **Deterministic Block-State Identities**: Blocks with state properties format deterministically as `minecraft:block[propA=valA,propB=valB]` with properties sorted alphabetically. This is the same canonicalization the MCA loader now applies to real oracle region files, so a value read from `.mca` and the same cell read from a JSON export are byte-identical strings (see `test_mca_canonical_state_matches_json_export_canonical_state`).
4. **Dense Intra-Section Cell Indexing**: Cell index strictly follows `((worldY - min_y) << 8) | (lz << 4) | lx`, i.e. per-section `(ly << 8) | (lz << 4) | lx`.
5. **Compact Section Palettes**: A section with exactly one palette entry omits the 4096-element `data` array; a section with more than one entry MUST carry `data` with exactly 4096 in-range indices. The strict loader rejects both a multi-entry palette missing `data` and a single-entry palette carrying one (ambiguous).
6. **Truthful stage/order/order_seed**: `stage` is `"FEATURES"` for `order1`/`order2` and `"FULL"` for `vanilla` (the oracle's real on-disk status, validated before export; see below). `order_seed` records the exact `Collections.shuffle` seed (`424242` for order1, `888888` for order2, `null` for vanilla).
7. **CARVERS-only margin recorded, never exported as chunks**: the 1-chunk prefix ring around `coverage` is generated only to `CARVERS` and never run through `FEATURES` (see `HeadlessNoise` calls in `BatchParityGate.main`). `margin` records those bounds with `"exported": false` so a consumer knows target-edge cells can be missing a feature that would have originated in that ring; this is a real limitation of the export window, not a claim of vanilla-equivalent behavior at the edge.
8. **Oracle integrity validated before any file is written**: for every target chunk, `BatchParityGate` requires the oracle region file to exist (without ever calling `RegionFile.open` on a missing path, that constructor auto-creates an empty region file, which would fabricate oracle data), the chunk slot to be present, `Status == "minecraft:full"`, and the chunk's own `xPos`/`zPos` NBT fields to match its region-file position. Any failure aborts before Order 1 generation starts and before any output file exists. A separate preflight, which runs whether or not a raw export was requested, also refuses to score at all when the oracle region directory is missing, a target region file is header-only (8,192 bytes or less, so it holds no chunks), or the probe CSVs load zero oracle rows, so a missing corpus can never be reported as a 0% match.
9. **Atomic publish**: all three files are written to a sibling `<dir>.tmp-<pid>` directory and only `Files.move`d into the final export path after all three are written; the export directory is refused if it already exists (no silently mixing a partial old run with a new one), and a JVM shutdown hook deletes the temp directory on any abnormal exit.

## Running BatchParityGate with Raw Export

### Invocation
Pass the export directory as the sole 7th positional argument. There is no system property or `--export-raw=` alias: one way in, so a caller can't have two disagreeing sources for the same setting.

```bash
# Compile once (offline, using the locally-cached JDK 25 toolchain and vanilla jar):
cd core && ./gradlew compileJava --offline \
  -PvanillaJar=$HOME/kestrel-run/vinner/META-INF/versions/26.2/server-26.2.jar \
  -PvanillaLibs=$HOME/kestrel-run/vinner
cd ..

# Direct Java invocation against the real seed-3527749958874813416 oracle
# (radius 8: coverage [-8..8]x[-8..8], 289 chunks; this is the only oracle
# capture currently on disk for this seed; there is no radius-16 oracle):
LIBS=$(find $HOME/kestrel-run/vinner/META-INF/libraries -name "*.jar" | tr "\n" ":")
CP="core/build/classes/java/main:$HOME/kestrel-run/vinner/META-INF/versions/26.2/server-26.2.jar:$LIBS"

# Run from a scratch directory: BatchParityGate/log4j writes logs/ relative
# to the process cwd, and running from the repo root pollutes the working
# tree with log files that don't belong in a commit.
mkdir -p /tmp/kestrel-raw-export && cd /tmp/kestrel-raw-export

$HOME/.local/toolchains/jdk-25.0.4.1+1/bin/java -cp "$CP" \
  dev.kestrel.worldgen.BatchParityGate \
  3527749958874813416 \
  $HOME/kestrel-run/live-seed-oracle-region \
  dummy-p2-blocks.csv \
  dummy-p2-full.csv \
  /tmp/kestrel-raw-export/gate.csv \
  8 \
  /tmp/kestrel-raw-export/raw-export
```

**Note on the CSV path argument**: pass an absolute path (or one with at least one directory component) for the 5th argument. This is the pre-existing legacy `outCsv` argument, unrelated to raw export: its `Files.createDirectories(outCsv.getParent())` call (unchanged by this feature) throws a raw `NullPointerException` if given a bare filename with no parent (e.g. `gate.csv`), since `Path.of("gate.csv").getParent()` is `null`. This is a latent bug in the pre-existing legacy CSV writer, confirmed still present and out of scope for this change (no generation-semantics or unrelated-code changes); tracked as a follow-up, not fixed here.

**Note on exit code**: `BatchParityGate`'s overall process exit code reflects the *legacy* CSV parity gate (P2/P3 cell-match rates against the oracle), which is a separate concern from whether the raw export succeeded. Seed `3527749958874813416` is not 100%-parity-exact against vanilla at this radius (about 99.8% order-1 cell parity), so a non-zero exit is expected here even when `order1.json`/`order2.json`/`vanilla.json` were all published correctly. Check the export directory's contents, not the exit code, to judge export success; the exit code still reliably signals `0` only when raw export was both requested and the oracle-validation/atomic-publish path completed *and* the legacy gate also found zero mismatches.

When no export path is supplied, `BatchParityGate` runs exactly its pre-existing legacy behavior (no validation pass, no temp directory, no raw files).

## Limitations

- **Only the radius-8 square is fully covered by the captured oracle.** The five region files in `$HOME/kestrel-run/live-seed-oracle-region` hold 2,554 chunk slots for seed `3527749958874813416`. Measured on 2026-09-25, 530 of those slots carry `Status: minecraft:full`, scattered over x -17..11 / z -40..11, because the capture followed a live player route, so the full set is not a square. All 289 chunks of `[-8..8]x[-8..8]` are inside that full set, which is why `targetHalf` 8 validates end to end, and there is no radius-16 (1,024-chunk) oracle: only 529 of those 1,024 chunks are `minecraft:full`. Requesting `targetHalf` beyond what the oracle region files actually cover fails the pre-export validation pass (missing region file or missing oracle chunk slot), by design.
- **`~/kestrel-run` is not guaranteed persistent** on this host (see `docs/RUNNING.md`): re-run `scripts/setup-env.sh` and re-verify `live-seed-oracle-region` exists before relying on it in a new session.
- **The CARVERS-only margin is a real generation-window gap**, not a proven vanilla-equivalent limitation. A target-edge chunk can legitimately lack a feature that should have spread in from its neighboring margin chunk, because margin chunks are never run through `FEATURES`. Treat edge-adjacent seam-analyzer findings with this in mind; the `margin` metadata block exists so downstream tooling can identify and optionally exclude them.
- **The exporter does not itself run `seam_analyzer.py`.** Chain the two tools manually (see below) or via a wrapper script; this keeps the export contract independently testable from the analysis step.

## Analyzing Exported Datasets with Seam Analyzer

```bash
# Compare Order 1 vs Vanilla
python3 harness/tools/seam_analyzer.py \
  --kestrel /tmp/kestrel-raw-export/raw-export/order1.json \
  --vanilla /tmp/kestrel-raw-export/raw-export/vanilla.json \
  --format table

# Compare Order 2 vs Vanilla
python3 harness/tools/seam_analyzer.py \
  --kestrel /tmp/kestrel-raw-export/raw-export/order2.json \
  --vanilla /tmp/kestrel-raw-export/raw-export/vanilla.json \
  --format table

# Check cross-order seam stability (Order 1 vs Order 2)
python3 harness/tools/seam_analyzer.py \
  --kestrel /tmp/kestrel-raw-export/raw-export/order1.json \
  --vanilla /tmp/kestrel-raw-export/raw-export/order2.json \
  --format table
```

The loader rejects (raises `ValueError`, no partial analysis) any `kestrel-raw-block-export-v1` payload with: a missing/non-decimal `seed`, missing/inconsistent `coverage`, duplicate or coverage-inconsistent chunk coordinates, a chunk with duplicate/missing sections relative to `min_y`/`height`, or a section whose palette/index counts or index ranges are inconsistent. It also rejects comparing two `kestrel-raw-block-export-v1` datasets whose declared `seed`/`height`/`min_y` disagree.

## Test Verification

Compile fresh Java first (required for the integration tests below to exercise current code, not a stale classfile), then run from a scratch cwd so log4j output doesn't land in the repo:

```bash
cd core && ./gradlew compileJava --offline \
  -PvanillaJar=$HOME/kestrel-run/vinner/META-INF/versions/26.2/server-26.2.jar \
  -PvanillaLibs=$HOME/kestrel-run/vinner
cd ..

mkdir -p /tmp/kestrel-test-run && cd /tmp/kestrel-test-run
PYTHONPATH=/path/to/repo python3 -m unittest discover -s /path/to/repo/harness/tools/tests -v
```

Tests that invoke the real `BatchParityGate` exporter (`TestJavaExporterIntegration`) require the JDK-25 toolchain, the vanilla jar/libs, a compiled `core/build/classes/java/main`, and `$HOME/kestrel-run/live-seed-oracle-region`; they `skipTest` cleanly (not silently pass) when any of these are unavailable, via a single `JAVA_PREREQS_AVAILABLE` gate checked once at import time.
